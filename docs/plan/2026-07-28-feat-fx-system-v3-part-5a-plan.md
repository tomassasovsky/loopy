## Overview

Bump the pedal wire protocol to v3: widen the state-frame mode field to 2 bits
so a third interaction mode (FX) fits on the wire, drive the on-pedal MODE LED
as a true tri-state mode indicator in both firmware trees, and give the app a
version-discovery seam so it never encodes v3 at a pedal that can't decode it.
This is the wire/codec/firmware half of the pedal FX mode; the app-side FX
interaction mode (button matrix, `InteractionMode.fx`, LED projection content)
is the neighboring part 5b. Everything here is host-testable: the firmware
codec is a host-compiled contract test, no board required.

## Dependencies

- None — no other part of this epic must merge first.
- **Coordinates with #331** (pedal auto-detect / firmware OTA): #331's part B
  (SysEx-capable inbound path) is the prerequisite for *automatic* version
  discovery via the identity reply; until it ships, a **manual pedal
  firmware-version setting** gates encoding [R6]. #331 also owns getting new
  firmware onto physical pedals (OTA) — including the physical 32u4 pedal,
  whose in-repo protocol copy is drifted to v1-only today
  (`hardware/firmware/segno_pedal_32u4/pedal_protocol.h:24`,
  `PEDAL_PROTOCOL_VERSION 0x01`); without that sync even today's v2 frames
  dark the physical pedal [R6]. This part de-drifts the *in-repo* copy (the
  diff-gate requires it); flashing the device rides #331.

## Tasks

### Wire format (Dart codec)

- [ ] `PedalMode` gains `fx`; rewrite the `pedal_mode.dart` doc comment (the
      "must stay a two-value enum" clause becomes the v3 rationale: the wider
      field + protocol bump happened here). `PedalStateFrame.mode` type is
      unchanged.
- [ ] Widen the state-frame mode field to **2 bits** [R8]. The flags byte is
      full at v2, so the second mode bit's home is **decided against the real
      frame** (`pedal_codec.dart:28-36`): prefer a spare bit in an existing
      logical-payload byte (byte 2 `activeBank` uses 1 of 8 bits; byte 3
      `selectedTrack` uses 3 of 8) so the 17-byte logical payload / 26-byte
      wire frame does not grow; v1/v2 encoders/decoders must be bit-for-bit
      unaffected. Define and test the reserved fourth mode value's decode
      behavior (degrade or reject — pick one, document it).
- [ ] Add `protocolVersionV3 = 0x03`; `decodeFrame` accepts v1/v2/v3; v1/v2
      frames never decode to `PedalMode.fx`. Update the codec doc-comment
      layout table + version history.
- [ ] **Downgrade projection at codec level [B10][R8]**: `encodeFrame` of a
      frame with `mode: fx` at `targetVersion` v2 or v1 writes the mode bit
      as `play` (mute); every other byte — including the `trackLeds` bytes
      that carry chain state in FX mode — is encoded identically to the v3
      path (only the mode-field downgrade differs). Tests pin this
      byte-for-byte against a v3 twin.
- [ ] **Never encode above negotiated**: `encodeFrame`'s implicit default
      must not silently become v3. `PedalRepository` resolves the target
      version — `min(known version, codec max)`, **unknown ⇒ v2** [R6] — and
      passes `targetVersion` explicitly at both call sites
      (`pedal_repository.dart:104,113-115`). Repository gains a
      target-version knob the app sets (from the manual setting now, from
      #331's identity reply later — same seam). `firmwareNeedsUpdate`
      (`pedal_codec.dart:282`) stays the pure signal; no UI banner here.
- [ ] Reserve/add the chain-state `PedalTrackLed` value(s) part 5b's FX-mode
      projection will emit (zero wire cost — the byte is an index [R8]); pick
      in coordination with part 5b's LED spec so 5b needs **no** further
      wire/firmware change.
